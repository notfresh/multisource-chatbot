## 消息组件化设计思路

### 核心设计理念

**将消息封装成一个独立的类（组件），所有消息相关的功能都通过这个组件来管理。**

### 1. 组件结构设计

```
MessageComponent (消息组件类)
├── 核心职责
│   ├── 渲染消息 DOM 结构
│   ├── 管理消息状态（原始内容、渲染状态等）
│   ├── 处理内容更新（流式输出）
│   └── 管理消息操作按钮（切换 Markdown、复制、删除等）
│
├── 内部结构
│   ├── rootElement (根元素 - .message)
│   ├── avatar (头像)
│   ├── contentWrapper (内容包装器)
│   │   ├── content (内容区域)
│   │   └── actionBar (操作按钮栏) ← 关键：统一管理所有按钮
│   └── timestamp (时间戳)
│
└── 公共接口
    ├── getElement() - 获取 DOM 元素
    ├── updateContent() - 更新内容（流式输出）
    ├── addActionButton() - 添加操作按钮
    └── destroy() - 销毁组件
```

### 2. 操作按钮栏（ActionBar）设计

**核心思路：将按钮区域独立出来，便于扩展**

```
actionBar (操作按钮栏)
├── 位置：在 contentWrapper 内部，content 下方
├── 结构：
│   └── <div class="message-actions">
│       ├── 切换 Markdown 按钮
│       ├── 复制按钮（未来）
│       ├── 删除按钮（未来）
│       ├── 编辑按钮（未来）
│       └── 更多按钮（未来）
│
└── 特点：
    ├── 统一管理所有按钮
    ├── 按钮可以动态添加/移除
    ├── 按钮样式统一
    └── 按钮事件统一处理
```

### 3. 组件接口设计

```javascript
// 组件构造函数
class MessageComponent {
  constructor(config) {
    // config 包含：
    // - message: 消息数据 { role, content, created_at }
    // - actions: 按钮配置数组（可选）
    // - onAction: 按钮点击回调（可选）
  }
  
  // 核心方法
```

### 5. 具体实现思路

#### 5.1 组件初始化流程

```
1. 创建根元素结构
   └── messageDiv (.message)
       ├── avatar
       ├── contentWrapper
       │   ├── content
       │   └── actionBar (操作栏，初始为空或包含默认按钮)
       └── timestamp

2. 渲染消息内容
   └── 根据是否有 Markdown 决定渲染方式

3. 初始化操作按钮
   └── 遍历配置的按钮数组
       ├── 检查显示条件
       ├── 创建按钮元素
       ├── 绑定点击事件
       └── 添加到 actionBar

4. 存储内部状态
   └── originalContent, isRendered, buttons 等
```

#### 5.2 按钮管理思路

```
// 按钮注册机制
class MessageComponent {
  constructor() {
    this.buttons = new Map(); // 存储所有按钮
    this.actionBar = null;    // 操作栏元素
  }
  
  // 注册默认按钮
  _initDefaultButtons() {
    // 切换 Markdown 按钮
    this.addActionButton({
      id: 'toggle-markdown',
      // ... 配置
    });
  }
  
  // 添加按钮（对外接口）
  addActionButton(config) {
    // 1. 检查条件
    if (config.condition && !config.condition(this.message)) {
      return;
    }
    
    // 2. 创建按钮元素
    const button = this._createButton(config);
    
    // 3. 存储按钮引用
    this.buttons.set(config.id, {
      element: button,
      config: config
    });
    
    // 4. 添加到操作栏
    this.actionBar.appendChild(button);
  }
  
  // 创建按钮元素
  _createButton(config) {
    const button = document.createElement('button');
    button.className = config.className || 'message-action-btn';
    button.textContent = config.text;
    button.dataset.actionId = config.id;
    
    // 绑定事件
    button.addEventListener('click', (e) => {
      config.onClick(this.message, this, e);
    });
    
    return button;
  }
}
```

### 9. 关键设计点总结

1. **单一职责**：组件只负责消息的渲染和状态管理
2. **开放扩展**：通过配置和接口添加新功能
3. **统一管理**：所有按钮在 actionBar 中统一管理
4. **状态封装**：原始内容、渲染状态等封装在组件内部
5. **事件隔离**：按钮事件在组件内部处理，外部通过回调通信
6. **易于测试**：组件独立，便于单元测试

### 10. 迁移策略

1. **第一步**：创建 `MessageComponent` 类，实现基本渲染
2. **第二步**：将 `createMessageElement` 改为使用组件
3. **第三步**：将切换 Markdown 功能迁移到组件内部
4. **第四步**：添加 actionBar 和按钮管理机制
5. **第五步**：逐步添加新按钮（复制、删除等）

这个设计让消息模块更模块化，添加新按钮和维护都更简单。
