## 三层架构重构方案

### 架构概览

```
┌─────────────────────────────────────┐
│   业务层 (Business Layer)           │  ← 表达"做什么"
│   MessageComponent                  │
│   - 协调业务逻辑                    │
│   - 处理用户交互                    │
└─────────────────────────────────────┘
           ↓ 依赖
┌─────────────────────────────────────┐
│   组件层 (Component Layer)          │  ← 表达"是什么"
│   - 领域模型 (Message, ModelResponse)│
│   - UI组件 (Button, ModelView等)    │
│   - 服务 (Renderer, Manager)        │
└─────────────────────────────────────┘
           ↓ 依赖
┌─────────────────────────────────────┐
│   基础设施层 (Infrastructure Layer) │  ← 表达"怎么做"
│   - DOM操作                         │
│   - 事件管理                        │
│   - 剪贴板                          │
│   - 工具函数                        │
└─────────────────────────────────────┘
```

### 2.3 管理器（Managers）

#### ModelResponseManager 管理器
```javascript
// 思考：如何管理多个模型回答？
class ModelResponseManager {
  constructor() {
    this.responses = new Map()  // Map<modelName, ModelResponse>
    this.views = new Map()      // Map<modelName, ModelResponseView>
  }
  
  add(model, content, messageId) {
    const response = new ModelResponse(model, content, messageId)
    this.responses.set(model, response)
    
    const view = new ModelResponseView(response)
    this.views.set(model, view)
    
    return view.render()
  }
  
  update(model, content) {
    const response = this.responses.get(model)
    if (response) {
      response.updateContent(content)
      const view = this.views.get(model)
      if (view) {
        view.updateContent(content)
      }
    }
  }
  
  toggle(model) {
    const view = this.views.get(model)
    if (view) {
      view.toggle()
    }
  }
  
  getExpanded() {
    // 返回当前展开的模型回答
    for (const [model, response] of this.responses) {
      if (response.isExpanded) {
        return response
      }
    }
    return null
  }
  
  getAll() {
    return Array.from(this.responses.values())
  }
}
```

思考：这一层定义业务概念和可复用组件，不关心具体如何操作 DOM，只关心业务逻辑。

## 第三层：业务层（Business Layer）

职责：协调组件，表达完整的业务流程

### MessageComponent（主组件）
```javascript
// 思考：消息组件是什么？如何协调各个部分？
class MessageComponent {
  constructor(messageData) {
    // 1. 创建领域模型
    this.message = new Message(messageData)
    
    // 2. 根据消息类型初始化不同的组件
    if (this.message.isAssistant()) {
      this.modelManager = new ModelResponseManager()
      this.modelSelector = new ModelSelector(
        ModelConfig.available,
        (model) => this.requestModel(model)
      )
    }
    
    this.actionBar = new ActionBar(this.getDefaultActions())
    this.contentRenderer = new ContentRenderer()
  }
  
  // 渲染主入口
  render() {
    // 使用 DOMUtils 创建根元素
    const root = DOMUtils.createElement('div', {
      className: `message ${this.message.role}`
    })
    
    // 添加头像
    const avatar = this.createAvatar()
    DOMUtils.append(root, avatar)
    
    // 添加内容区域
    const contentWrapper = this.createContentWrapper()
    DOMUtils.append(root, contentWrapper)
    
    // 添加时间戳
    const time = this.createTime()
    DOMUtils.append(root, time)
    
    return root
  }
  
  // 创建内容区域
  createContentWrapper() {
    const wrapper = DOMUtils.createElement('div', {
      className: 'message-content-wrapper'
    })
    
    if (this.message.isUser()) {
      // 用户消息：简单渲染
      const content = this.contentRenderer.render(this.message.content)
      DOMUtils.append(wrapper, content)
    } else {
      // 助手消息：多模型回答
      // 1. 添加模型选择器
      const selector = this.modelSelector.render()
      DOMUtils.append(wrapper, selector)
      
      // 2. 添加已有模型回答
      const existingResponses = this.message.alternative_responses || []
      existingResponses.forEach(response => {
        const view = this.modelManager.add(
          response.model,
          response.content,
          response.id
        )
        DOMUtils.append(wrapper, view)
      })
      
      // 3. 如果有默认模型回答，添加它
      if (this.message.content) {
        const defaultModel = this.message.model || ModelConfig.default
        const view = this.modelManager.add(
          defaultModel,
          this.message.content,
          this.message.id
        )
        DOMUtils.append(wrapper, view)
        // 默认展开
        this.modelManager.toggle(defaultModel)
      }
    }
    
    // 4. 添加操作栏
    const actionBar = this.actionBar.render()
    DOMUtils.append(wrapper, actionBar)
    
    return wrapper
  }
  
  // 请求模型回答（业务逻辑）
  requestModel(modelName) {
    // 1. 更新模型选择器状态
    this.modelSelector.updateModelStatus(modelName, false)
    
    // 2. 创建占位符视图
    const view = this.modelManager.add(modelName, '', null)
    const wrapper = this.root.querySelector('.message-content-wrapper')
    DOMUtils.append(wrapper, view)
    
    // 3. 调用外部 API（在 chat.js 中定义）
    if (typeof requestModelResponse === 'function') {
      const userMessageId = this.findUserMessageId()
      requestModelResponse(userMessageId, modelName, this)
    }
  }
  
  // 更新模型回答（业务逻辑）
  updateModelResponse(modelName, content) {
    this.modelManager.update(modelName, content)
    this.modelSelector.updateModelStatus(modelName, true)
  }
  
  // 复制内容（业务逻辑）
  copyContent() {
    let textToCopy = ''
    
    if (this.message.isUser()) {
      textToCopy = this.message.content
    } else {
      const expanded = this.modelManager.getExpanded()
      if (expanded) {
        textToCopy = expanded.content
      }
    }
    
    if (textToCopy) {
      ClipboardService.copy(textToCopy, this.actionBar.getCopyButton())
    }
  }
  
  // 获取默认操作
  getDefaultActions() {
    return [
      {
        id: 'copy',
        text: '📋 复制',
        onClick: () => this.copyContent()
      }
    ]
  }
  
  // 工具方法
  createAvatar() {
    return DOMUtils.createElement('div', {
      className: 'message-avatar',
      textContent: this.message.isUser() ? 'U' : 'AI'
    })
  }
  
  createTime() {
    if (!this.message.createdAt) return null
    
    return DOMUtils.createElement('div', {
      className: 'message-time',
      textContent: Utils.formatDate(this.message.createdAt)
    })
  }
  
  findUserMessageId() {
    // 查找对应的用户消息ID
    const prevElement = this.root.previousElementSibling
    if (prevElement && prevElement.dataset.messageId) {
      return parseInt(prevElement.dataset.messageId)
    }
    return this.message.id
  }
  
  // 公共 API
  getElement() {
    if (!this.root) {
      this.root = this.render()
    }
    return this.root
  }
  
  destroy() {
    // 清理事件监听
    // 清理 DOM 引用
  }
}
```

思考：这一层只关心业务逻辑和流程，不关心具体如何创建 DOM 或处理事件，只表达"做什么"。

## 三层关系总结

### 依赖关系
```
业务层 (MessageComponent)
    ↓ 使用
组件层 (ModelResponseManager, ModelResponseView, Button等)
    ↓ 使用
基础设施层 (DOMUtils, EventUtils, ClipboardService)
```

### 数据流
```
用户操作
    ↓
MessageComponent (业务层：处理业务逻辑)
    ↓
ModelResponseManager (组件层：管理状态)
    ↓
ModelResponseView (组件层：更新视图)
    ↓
DOMUtils (基础设施层：更新 DOM)
```

### 职责划分

| 层级 | 职责 | 关心什么 | 不关心什么 |
|------|------|----------|------------|
| 业务层 | 协调业务流程 | 做什么 | 怎么做 |
| 组件层 | 定义业务概念和组件 | 是什么 | 如何实现 |
| 基础设施层 | 提供基础能力 | 怎么做 | 为什么做 |

## 重构优势

### 1. 代码更直观
```javascript
// 现在：_addModelResponse() 做了很多事情
// 重构后：
this.modelManager.add(model, content, messageId)  // 表达意图
this.modelSelector.updateModelStatus(model, true)  // 表达意图
```

### 2. 职责清晰
- 业务层：只关心业务流程
- 组件层：只关心业务概念和组件
- 基础设施层：只关心技术实现

### 3. 易于测试
- 可以单独测试 ModelResponseManager（纯逻辑）
- 可以 Mock 基础设施层
- 可以单独测试各个组件

### 4. 易于扩展
- 添加新模型：修改 ModelConfig
- 添加新组件：在组件层添加
- 添加新功能：在业务层组合现有组件
