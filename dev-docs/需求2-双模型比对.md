# 实施方案


## 双模型比对功能实现方案

### 一、功能需求分析

**两种实现思路：**

#### 方案 A：按需查询（优先实现，默认方案）
1. 默认只调用一个模型（DeepSeek）
2. 用户可以通过按钮或操作主动触发查看另一个模型（通义千问）的回答
3. 按需查询时，另一个模型**不知道前者的回答**，不把前者的回答作为上下文
4. 两个响应都显示，通义千问默认折叠（如果已生成）
5. 用户体验：先看 DeepSeek 的回答，需要时再查看通义千问的回答

#### 方案 B：并行请求（后续实现）
1. 同时调用两个模型（DeepSeek 和通义千问）
2. 两个响应都显示，通义千问默认折叠
3. 用户可手动展开通义千问的响应
4. 两个模型使用相同的 API 结构，仅 model 参数不同

**当前实现优先级：**
- ✅ **第一阶段：实现方案 A（按需查询）**
- ⏳ **第二阶段：实现方案 B（并行请求）**

### 四、实现细节

#### 0. 按需查询时构建历史消息的规则（核心逻辑）

**核心原则：**
当用户按需查询另一个模型的回答时，构建历史消息需要遵循以下规则，确保上下文公平且连贯：

1. **排除当前要替换的 assistant 消息**：排除最近一条 assistant 消息（即当前问题的已有回答）
2. **同类模型优先**：对于每一轮用户消息，如果该轮有同类模型的回答，优先使用同类模型的回答
3. **没有同类时使用第一个**：如果该轮没有同类模型的回答，使用第一个其他模型的回答（按时间顺序）

**详细说明：**

按需查询的目的是让另一个模型基于相同的上下文生成回答，但需要排除当前问题的已有回答。同时，为了保持对话的连贯性和一致性，对于历史中的每一轮对话，优先选择同类模型的回答。

**场景示例：**

##### 场景1：第一次按需查询（第三轮）

**当前对话历史：**
```
[(user-promt1), (deepseek, message1), 
 (user-promt2), (deepseek, message2), 
 (user-promt3), (deepseek, message3)]
```

**用户操作：** 点击 message3，请求千问回答

**构建给千问的历史消息：**
```
[(user-promt1), (deepseek, message1), 
 (user-promt2), (deepseek, message2), 
 (user-promt3)]
```

**逻辑说明：**
- 第1轮：只有 deepseek 的回答 → 保留（因为没有千问，使用第一个其他模型的回答）
- 第2轮：只有 deepseek 的回答 → 保留（因为没有千问，使用第一个其他模型的回答）
- 第3轮：排除 deepseek message3（当前要替换的）
- 这样千问和 DeepSeek 在回答 user-promt3 时，都看到了相同的上下文（前两轮的完整对话）

##### 场景2：第二次按需查询（第五轮）

**当前对话历史：**
```
[(user-promt1), (deepseek, message1), 
 (user-promt2), (deepseek, message2), 
 (user-promt3), (deepseek, message3), (qianwen, message3),  ← 第三轮有两个回答
 (user-promt4), (deepseek, message4),
 (user-promt5), (deepseek, message5)]
```

**用户操作：** 点击 message5，请求千问回答

**构建给千问的历史消息：**
```
[(user-promt1), (deepseek, message1), 
 (user-promt2), (deepseek, message2), 
 (user-promt3), (qianwen, message3),   ← 优先使用千问的回答
 (user-promt4), (deepseek, message4),
 (user-promt5)]
```

**逻辑说明：**
- 第1轮：只有 deepseek 的回答 → 保留（因为没有千问，使用第一个其他模型的回答）
- 第2轮：只有 deepseek 的回答 → 保留（因为没有千问，使用第一个其他模型的回答）
- 第3轮：有千问的回答 → **优先使用千问，排除 deepseek**（同类模型优先）
- 第4轮：只有 deepseek 的回答 → 保留（因为没有千问，使用第一个其他模型的回答）
- 第5轮：排除 deepseek message5（当前要替换的）

**这样设计的好处：**
1. **上下文公平**：两个模型在回答同一个问题时，都看到相同的上下文（排除当前问题的已有回答）
2. **对话连贯**：后续查询时，能看到之前所有模型的回答，保持对话连贯性
3. **同类优先**：优先使用同类模型的回答，保持对话风格的一致性
4. **公平对比**：每个模型在回答时，都基于相同的对话历史，只是排除当前问题的已有回答

**实现要点：**
- 需要根据 `model` 字段识别消息来源
- 需要按 `order_index` 或时间顺序处理消息
- 对于每一轮用户消息，需要检查是否有同类模型的回答
- 如果没有同类模型的回答，选择第一个其他模型的回答

#### 1. 按需查询实现（第一阶段）

**后端实现：**
```python
# 伪代码示例
def generate_alternative_model_response(conversation_id, target_message_id, model_name, stream=False):
    """
    按需查询另一个模型的回答
    
    关键：构建上下文时，遵循"同类模型优先"规则，排除当前要替换的 assistant 消息
    
    Args:
        conversation_id: 会话ID
        target_message_id: 要替换的 assistant 消息ID
        model_name: 要使用的模型名称（如 'qwen-max'）
        stream: 是否流式输出
    """
    # 获取目标消息对应的用户消息
    target_message = Message.query.get(target_message_id)
    user_message = get_user_message_for_assistant(target_message)
    
    # 构建内存（遵循"同类模型优先"规则）
    memory = build_memory_for_alternative_model(
        conversation_id, 
        target_message_id,
        model_name  # 用于判断"同类模型"
    )
    
    # 获取指定模型的 LLM 实例
    llm = get_llm('302ai', model_name=model_name)
    
    # 生成回答
    if stream:
        return generate_stream(llm, memory, user_message)
    else:
        return generate_normal(llm, memory, user_message)

def build_memory_for_alternative_model(conversation_id, target_message_id, target_model_name):
    """
    构建按需查询时的对话历史
    
    规则：
    1. 排除当前要替换的 assistant 消息（target_message_id）
    2. 对于每一轮用户消息，优先使用同类模型的回答
    3. 如果没有同类模型的回答，使用第一个其他模型的回答
    """
    # 获取所有消息（按顺序）
    messages = Message.query.filter_by(
        conversation_id=conversation_id
    ).order_by(Message.order_index.asc()).all()
    
    # 按用户消息分组，构建轮次
    rounds = []  # [(user_msg, [assistant_msgs]), ...]
    current_user_msg = None
    current_assistant_msgs = []
    
    for msg in messages:
        if msg.role == 'user':
            # 保存上一轮
            if current_user_msg:
                rounds.append((current_user_msg, current_assistant_msgs))
            # 开始新的一轮
            current_user_msg = msg
            current_assistant_msgs = []
        elif msg.role == 'assistant':
            # 跳过要替换的消息
            if msg.id == target_message_id:
                continue
            current_assistant_msgs.append(msg)
    
    # 保存最后一轮
    if current_user_msg:
        rounds.append((current_user_msg, current_assistant_msgs))
    
    # 构建内存
    memory = ConversationBufferMemory()
    for user_msg, assistant_msgs in rounds:
        # 添加用户消息
        memory.chat_memory.add_user_message(user_msg.content)
        
        # 选择 assistant 消息
        selected_assistant = None
        # 优先选择同类模型的回答
        for assistant_msg in assistant_msgs:
            if assistant_msg.model == target_model_name:
                selected_assistant = assistant_msg
                break
        # 如果没有同类模型，使用第一个其他模型的回答
        if not selected_assistant and assistant_msgs:
            selected_assistant = assistant_msgs[0]
        
        # 添加选中的 assistant 消息
        if selected_assistant:
            memory.chat_memory.add_ai_message(selected_assistant.content)
    
    return memory
```

```python
# 伪代码示例
from concurrent.futures import ThreadPoolExecutor

def generate_multi_model_response(...):
    with ThreadPoolExecutor(max_workers=2) as executor:
        future_deepseek = executor.submit(call_deepseek, ...)
        future_qwen = executor.submit(call_qwen, ...)
        
        # 等待两个结果
        deepseek_result = future_deepseek.result()
        qwen_result = future_qwen.result()
        
        return {
            'deepseek': deepseek_result,
            'qwen': qwen_result
        }
```

#### 3. 中断处理实现

**后端中断处理：**
```python
# 伪代码示例
import threading

def generate_multi_model_response_stream(..., stop_event=None):
    stop_event = stop_event or threading.Event()
    
    # DeepSeek 流式输出
    for chunk in deepseek_stream:
        if stop_event.is_set():
            break  # 立即停止
        yield {'type': 'chunk', 'model': 'deepseek-chat', 'chunk': chunk}
    
    if stop_event.is_set():
        yield {'type': 'interrupted'}
        return
    
    # 切换到通义千问
    yield {'type': 'model_switch', 'model': 'qwen-max'}
    
    # 通义千问流式输出
    for chunk in qwen_stream:
        if stop_event.is_set():
            break  # 立即停止
        yield {'type': 'chunk', 'model': 'qwen-max', 'chunk': chunk}
```

## 风险提示
